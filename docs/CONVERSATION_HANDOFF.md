# 회사 PC Codex 대화 인수인계

기준일: 2026-10-06, 한국 시간. 이 문서는 지금까지의 대화에서 이어가야 할 요청·결정·답변·진행 상태를 정리한 것이다. 전체 대화 원문을 내보낸 파일은 아니며, 비밀번호·비밀키·실제 회원 개인정보를 포함하지 않는다. 기술적인 최신 검증은 [HANDOFF](HANDOFF.md) 최상단을 함께 읽는다.

## 사용자의 최종 목적과 작업 방식

대광교회 홈페이지·관리자·모바일 앱을 실제 교인이 사용할 수 있는 상태로 완성하고 배포한다. 사용자는 “실제 연결 전까지 할 수 있는 모든 작업”, 디자인/UIUX 개선, 실제 교인/관리자에게 도움이 되는 기능을 요청했고, 이후 DB 비밀번호를 재설정해 실제 연결까지 진행했다. 가능한 개발·검증은 계속 진행하고, 매 단계마다 같은 확인 질문을 반복하지 않는다. 사용자는 bash로 실행한다.

이번 요청: “회사컴퓨터에서 이어서 진행할수있도록 깃에다가 올려주고 진행사항 대화내용포함해서 회사컴퓨터에서 코덱스를통해 진행할수있도록해줘”. 코드·자산·설계·검증·이 문서를 함께 Git에 보관한다. 집 PC의 실행 중 서버/브라우저 로그인/환경변수/도구 캐시를 회사 PC로 복사했다고 간주하지 않는다.

## 대화에서 확정한 제품·디자인 기준

- 공식 교회명은 **대한예수교장로회 대광교회**. 교단명은 작은 글씨, 대광교회는 큰 글씨로 위계를 둔다.
- 약 40명 규모, 어른 약 20명이고 나머지는 청소년·청년. 사용량이 적어도 혼자 말씀·묵상·기도에 도움받는 앱이 중요하다. 참여 경쟁·출석 점수·매일 기록 강요를 피한다.
- 첫 실행은 공개 내용을 볼 수 있고 개인 기록 기능에서 로그인한다. 개인 묵상과 기도는 비공개이며 관리자가 임의로 읽지 않는다. 앱 가입과 교회 등록 성도 확인은 별개다.
- 홈페이지는 명료하되 기계적으로 같은 영역을 반복하는 화면을 원하지 않는다. “한 영역의 메시지 하나”는 관련 콘텐츠를 하나의 주제로 묶으라는 의미다. 이미지·크기·배치·여백의 변화와 따뜻한 교회 분위기를 유지한다. 어색한 아치 장식을 추가하지 않는다.
- 기본 글꼴은 Pretendard/Noto Sans 계열. 부드러운 명조 표현이 필요한 일부 위치만 KoPub바탕을 고려한다. 임의의 다른 바탕체로 대체하지 않는다.
- 홈페이지와 앱의 주보·주일 말씀·첫시간을 중복 등록하지 않는다. 통합 관리자에서 동일 원본과 공개 상태를 관리한다.
- 소속/전도회별 소식은 관심 구독과 승인 소속을 분리한다. 관심 선택만으로 소속 전용 공지 열람 권한을 주지 않는다.
- 기존 Figma `독산대광교회 앱 UX · Wireframe`의 `02 UX 명세`, `03 App UI`에 88개 화면/상태 기획이 있다. 화면 기획이 없다고 가정해서 다시 시작하지 않는다. Figma 원본을 삭제·대체하지 않는다.
- Figma: https://www.figma.com/design/rYXtTqmldFTgsYHoRfaT40

## 최근 알림 대화와 결정

사용자는 앱 내부 알림만으로는 의미가 없다며 “푸시가 필요할 것 요소 구분하고 푸시기능을 넣어줘”, “무료로 할 수 있는 것 차원에서 진행”을 요청했다. 이어 Firebase가 있으면 안드로이드만 가능한지 물었다. iPhone도 가능하지만 Apple/APNs 인증과 앱 서명이 별도로 필요하다고 설명했다. 최종적으로 **안드로이드 / Expo·Firebase 계정 없음**이라고 답했다.

구현한 방식은 Expo Push Service → FCM(Android) / APNs(iOS)다. 푸시 전송 무료 범위와 서버/빌드/스토어 비용은 구분한다. iPhone의 Apple 개발자 등록은 별도이며 비영리기관 면제 가능성은 승인 여부를 확인해야 한다. 지금은 유료 플랜을 신청하지 않았다.

- 첫시간: 당일 공개 말씀을 선택 시각 이후 하루 한 번.
- 새 예배 말씀, 중요 공지, 선택한 새 행사 소식: 원본당 한 번. 일반 소식은 22~08시 보류, 기기당 하루 최대 5건.
- 본인이 만든/저장한 일정: 당일 시작 30분 전, 종일 일정은 오전 8시. 새벽 일정 경계/지연 제한은 상세 문서를 따른다.
- 기기 권한/등록과 계정별 수신 항목은 구분한다. 기본은 꺼짐. 로그아웃·권한 해제·계정 전환·탈퇴와 연결했다.
- 개인 제목·메모·기도·상담 내용은 잠금 화면에 보내지 않는다. 알림 탭 후 본인 인증과 원본 공개 여부를 재검사한다.
- 일반 공지/주보/사진마다 푸시를 늘리지 않는다. 소속·상담 푸시는 운영 정책 미정으로 아직 활성 대상이 아니다.

**코드 구현과 DB 적용은 완료했지만 실제 발송은 꺼져 있다.** Expo/FCM 프로젝트·키, 배포 HTTPS 주소, 5분 주기 호출, 실제 APK 설치/수신 검증은 아직 없다. 브라우저나 Expo export 성공을 휴대폰 수신 성공으로 표현하지 않는다. [기능 분석](push-design.md), [연결 절차](notifications.md).

## 작업 상태와 다음 순서

1. 회사 PC의 현재 Git 변경을 보존하고 원격 main을 가져온다. [회사 PC 점검표](company-pc-checklist.md)를 따라 의존성과 비밀 환경변수를 확인한다. 기존 환경 파일을 덮어쓰지 않는다.
2. 세 프로젝트를 실행하고 현재 화면/관리자 로그인/공개 API를 확인한다. DB는 이미 12개 migration 적용 상태다. **reset/seed/과거 migration 재실행을 하지 않는다.** 회사 PC가 동일 DB를 가리키는지 먼저 확인한다.
3. Firebase와 Expo 모두 사용자의 같은 Google 계정을 사용한다(2026-10-09 확인). Firebase 교회용 프로젝트/Android 등록과 Expo EAS 프로젝트 연결 여부를 확인해 Android 푸시 연결을 이어간다. 상세 순서는 notifications.md에 있다. 이미 구현한 큐·토큰·화면을 처음부터 다시 만들지 않는다.
4. HTTPS 호스팅/도메인, Supabase Cron/Vault, FCM 자격, Android APK와 본인 동의 기기를 연결한다. 교인 대상 일괄 시험 발송은 하지 않는다. 실제 기기에서 닫힘/배경/권한 거부/탭/로그아웃/계정 전환/일정 변경을 검증한다.
5. 미정 운영 정보, SMTP/약관/가입/탈퇴, 모임/돌봄 설정을 확정되는 대로 연결한다. 탈퇴·가입·돌봄·모임 플래그가 기본 비활성인 이유를 보존한다.
6. 두 실제 테스트 회원의 소유자 격리, 관리자 저장 → 홈페이지/앱 반영, 실제 교인 사용성을 확인하고 배포 검증을 마친다.

최근 완료 검증은 단위/체험 79개 + 격리 DB 45개 = 124개, 타입/lint/패키지 경계, 관리자 빌드, 웹/Android/iOS 번들, 가짜 인증/API 브라우저 검사다. 실제 DB의 새 푸시 테이블 RLS·공개 접근 차단을 확인했고 실제 발송/회원 삭제는 하지 않았다. 상세 제한과 최근 수정은 HANDOFF 최상단이 기준이다.

## 회사 PC에서 Codex에게 붙여 넣을 요청

> 이 저장소에서 대광교회 홈페이지·관리자·앱 작업을 이어서 진행해줘. 먼저 AGENTS.md, docs/CONVERSATION_HANDOFF.md, docs/HANDOFF.md 최상단, docs/PROJECT_CONTEXT.md, docs/company-pc-checklist.md, docs/notifications.md를 읽고 현재 Git 상태와 회사 PC 환경을 확인해줘. 회사 PC의 기존 변경·환경 파일을 보존하고 비밀값은 출력하지 마. DB migration은 집 PC에서 12개까지 적용했고 실제 푸시는 아직 꺼져 있어. 내 기기는 안드로이드이고 Firebase는 기존 Google 계정을 사용해. 교회용 Firebase 프로젝트와 Expo 계정 준비 여부를 확인해서 프로젝트 연결, HTTPS 서버·주기 작업, APK 실기기 푸시 검증부터 이어가자. 이미 만든 기능과 디자인을 처음부터 다시 만들지 말고 가능한 작업은 계속 진행해줘.
