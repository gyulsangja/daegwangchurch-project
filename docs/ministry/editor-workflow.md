# 통합 작성 화면 (2026-11-03)

## 사용 흐름

통합 관리의 기존 등록·수정 dialog를 목록 → 전체 작성 화면 → 저장/목록 복귀로 전환했다. 말씀, 주보 정보·PDF·삭제, 예배 회차, 일정·공지, 사진첩, 교회 안내, 모임·모임 공지, 회원, 문의·돌봄 접수, 상담·기도·계획, 교육·봉사, 사용자 권한이 대상이다. 이미 일반 페이지인 설정·교적 화면은 유지한다. 삭제·공개·권한 변경의 짧은 확인 절차는 유지한다.

`EditorProvider`가 목록을 마운트한 채 숨기고 `EditorPage`를 main의 일반 문서 흐름에 표시한다. 목록 필터·선택·스크롤을 보존하며 작성 내용은 열었을 때만 마운트한다. 창 내부 스크롤이나 모달 포커스 제한은 없다. 공통 뒤로가기, 변경 여부 안내, 하단 저장 영역, 미저장 이탈 경고를 제공한다. 브라우저 뒤로가기도 목록으로 복귀한다. 입력 초안을 영구 저장하는 기능은 아니다.

데스크톱은 관련 입력을 2열로 묶고 긴 본문과 복잡한 선택 영역은 전체 폭을 사용한다. 모바일은 1열이다. 공지·일정의 선택 첨부 영역은 접을 수 있다. 말씀은 기존 영상 미리보기와 기본 정보 구성을 유지하면서 공통 작성 프레임에 맞췄다.

## 조회와 코드 정리

- `sharedRead`는 동일한 `/api/v1/` GET이 동시에 진행 중일 때만 공유한다. 응답별 clone, 소비자별 취소를 지원하며 완료 후 캐시를 보관하지 않는다. POST나 권한 검사에는 적용하지 않는다.
- 모임 공지 저장은 불필요한 모임 전체 목록을 다시 조회하지 않는다. 구성원 변경은 모임 인원 정보도 갱신한다.
- 주보·말씀은 종류별 갱신 키를 사용한다. 말씀 수정·삭제로 연결 주보의 제목이 바뀔 수 있는 경우에는 양쪽을 갱신한다.
- 사진첩·교회 안내에서 취소된 이전 조회가 새 결과를 덮어쓰지 않도록 했다.
- 교육·봉사 그룹 구성 및 목회 활동의 교인·계획 조회를 Map 인덱스로 정리했다.
- 서버의 요청 단위 인증 공유는 유지하고 저장 시 권한·버전 재검사는 제거하지 않았다. API 전체를 영구 캐시하거나 백엔드를 분리한 변경은 아니다.

## 검증

목회 테스트 98개, 목회 타입 검사·프로덕션 빌드, 격리 Chrome 데스크톱/모바일 회귀 검증을 수행했다. API 저장은 모의 응답으로 검증했으며 운영 자료·권한·파일을 변경하지 않았다. 공통 페이지 테스트는 `npm run test:ministry:browser`이며 격리 개발 서버만 허용한다. 기본 포트는 3002, 별도 검토 서버는 `MINISTRY_REVIEW_URL`로 지정한다. 실제 운영 모드 개발 서버에는 실행하지 않는다.

브라우저 검증 범위: 생성·수정·저장·취소, 미저장 경고, 브라우저 뒤로가기, 취소 시 불필요한 목록 GET 없음, 첨부 보존·자동 축소·업로드, 버전 전달, 모바일 넘침과 JS 오류. 실기기/실운영 사용자별 저장까지 자동 검증한 것은 아니다.
