# 홈페이지·앱·목회 통합 관리

2026-10-28 사용자 요구: 홈페이지 방문 문의, 상담·심방 요청, 앱 모임·소속을 목회 업무와 연결하고 최종적으로 하나의 관리자 화면에서 운영한다.

## 현재 확인한 범위

- 홈페이지 Inquiry, 앱 MemberCareRequest, 교인 확인 ChurchMembership, 앱 ChurchGroup/GroupMembership과 목회 교적·연간 편성은 별도 원본이다.
- 목회 /integration은 기존 CMS 링크, 확인된 앱 계정과 교적 연결, 상담 요청 메타데이터의 목회 일정 인계 코드만 있다. 운영 브리지는 직전 배포 기록에서 비활성 상태이며 이번 조사에서 활성화하지 않았다.
- 방문 문의와 앱 소속의 통합 처리 및 접수 상태 되돌리기는 미구현이다. 기존 링크 화면을 통합 완료로 취급하지 않는다.

## 목표와 원본 책임

통합 관리 화면은 목회시스템을 중심으로 만든다. 홈페이지와 앱은 공개 콘텐츠 및 회원 본인의 허용된 정보만 읽는다. 화면 통합을 위해 공개 서버에 ministry DB 권한을 부여하지 않는다. 당장 프레임워크 교체나 별도 백엔드 재작성은 필요 없다.

| 업무 | 원본 | 통합 화면의 동작 |
| --- | --- | --- |
| 공지·주보·설교·행사·사진 | 기존 CMS | 기존 편집·발행 서비스를 재사용하고 홈페이지·앱 동시 반영 |
| 홈페이지 방문 문의 | 기존 Inquiry | 통합 접수함에서 담당·연락·처리 관리, 확인 후 새가족 교적 또는 목회 일정 연결 |
| 앱 상담·심방 요청 | 기존 MemberCareRequest | 담당자가 접수·일정 협의·진행·완료 처리하고 목회 활동 연결 |
| 교적·직분·가구·연도별 조직 | 목회시스템 | 관리 원본, 앱 계정은 교적에 명시적 연결 |
| 앱 모임·소속 | 기존 그룹을 목회 조직 ID에 매핑 | 운영 중인 연도의 공식 소속만 앱에 반영, 관심 구독은 별도 유지 |
| 개인 묵상·기도 | 회원 개인 영역 | 통합 운영자에게 자동 공개하지 않음 |

## 접수 흐름

문의/요청 → 통합 접수함 → 담당자 배정·연락 → 기존 교인/가구/조직 또는 새가족 연결 → 상담·심방 일정 → 결과·후속 기록.

- 비회원 문의도 받을 수 있으며, 문의 접수만으로 교적이나 앱 계정을 생성하지 않는다.
- 이름·전화가 같다고 자동 연결하지 않는다. 기존 교적 후보를 확인하여 명시적으로 연결한다.
- 하나의 원본 접수 ID는 같은 목회 인계 대상으로 중복 생성되지 않는다. 재시도와 두 담당자의 동시 처리를 검증한다.
- 원본 상태와 회원에게 보일 안내를 구분한다. 앱에는 본인의 접수 상태·허용된 일정 안내만 제공하고 내부 상담 기록·목회 기도·담당자 메모는 보내지 않는다.
- 현재 상담 담당자 설정을 유지한다. 목회 CARE 권한만 생겼다고 기존 요청 본문을 모두 열람하도록 넓히지 않는다. 접수 담당/목회 담당 권한의 명시적 연결과 회수 반영을 구현한다.
- 현재의 원본 보관·만료·삭제 정책을 존중한다. 목회 결과 기록의 보관·삭제 범위는 별도로 정하고 원본 만료 후 본문 복제로 우회 보존하지 않는다.

## 조직과 앱 소속

- 조직 명칭 대신 고정 ID로 연결한다. 앱 모임은 공지·푸시 채널, 목회 조직은 연간 구성과 역할 이력이다.
- 목회 조직에서 앱 노출/공지 대상으로 지정한 조직만 연결한다. 모든 내부 봉사팀을 자동 공개하지 않는다.
- 연도 준비·복사는 앱 소속에 영향을 주지 않는다. 운영 연도 전환과 실제 적용일에 맞춰 반영한다.
- 교적에 계정이 없는 교인도 유지한다. 앱 계정이 연결된 교인에게만 공식 소속을 반영한다.
- 관심 모임 구독을 공식 소속으로 승격하지 않는다. 회장·총무·회계 같은 조직 역할을 관리자 권한으로 자동 승격하지 않는다.
- 통합 전에는 양쪽 자료의 차이를 검토한다. 목회 편성으로 기존 앱 명단을 일괄 덮어쓰지 않는다.

## 단계와 완료 기준

### 선행 필수: 역할·담당 범위·정보 민감도에 따른 접근

2026-10-28 사용자 보완: 통합 시스템은 홈페이지/앱 관리자뿐 아니라 당회원·부서장·부교역자·담임목회자가 사용해야 하며 역할의 성격에 따라 접근이 달라야 한다. 아래는 설정 가능한 초기 템플릿 제안이며 아직 운영 권한을 변경한 것은 아니다.

| 역할 템플릿 | 기본 업무 제안 | 별도 지정이 필요한 범위 |
| --- | --- | --- |
| 홈페이지·앱 운영자 | 공지/주보/설교/행사/사진 편집·발행, 공개 안내, 알림 운영 | 일반 방문 문의 담당, 회원 승인/소속 관리, 교적 연락처, 상담 접수/본문 |
| 교회 행정 담당 | 교적/가구/직분/조직/연간 편성, 교인 확인 연결, 일반 접수 | 상담·심방 민감 본문, 인쇄/내보내기, 계정·권한 관리 |
| 부서장·조직 리더 | 지정 부서 명단·출석·교육·모임 소식 | 연락처/주소 열람, 타 부서 접근, 민감 기록, 일괄 내보내기 |
| 부교역자 | 담당 교인/가구/부서의 목회 계획·돌봄 일정·기록 | 전체 교회 교적, 다른 담당자의 비공개 상담, 권한 관리 |
| 담임목회자 | 교회 전체 목회 현황·계획·교적 및 지정된 돌봄 관리 | 시스템 권한 부여, 콘텐츠 발행, 반출 등 별도 업무 능력 |
| 당회원 | 교회 운영·목회 현황의 요약 통계, 배정된 심의/운영 자료 | 개인 상담·기도 원문, 상세 연락처, 담당 외 개인 기록, 수정/삭제 |
| 시스템 권한 관리자 | 초대·역할·담당 범위·권한 회수·접근 감사 | 상담/목회 기록 본문 열람은 관리 권한만으로 부여하지 않음 |

- 직분(장로/집사 등), 조직 역할(회장/총무/교사), 시스템 접근 역할은 별도다. 직분 승진·조직 배정만으로 보안 권한이 확대되지 않는다. 기존에 명시 승인된 관리자 권한은 별도 전환 검토 없이 축소/확대하지 않는다.
- 권한은 `업무 능력 × 담당 범위 × 데이터 수준`으로 판정한다. 업무별 조회/작성/수정/승인/발행/삭제/인쇄·내보내기를 구분한다. 범위는 전체 교회/담당 조직/배정 교인·가구/본인 작성 기록으로 지정한다. 상담의 비공개·담당 제한은 일반 역할의 넓은 범위보다 우선한다.
- 다중 역할 허용: 홈페이지 관리자이면서 부서장인 경우 각 역할의 능력과 해당 범위를 각각 평가한다. 한 역할의 전체 교회 범위가 다른 역할의 민감 업무에 전파되지 않는다.
- 당회원에게 상담 원문을 일괄 공개하지 않는다. 현황 통계도 소수 인원의 민감 사실이 드러나지 않도록 범위를 검토한다. 심의 자료를 제공할 경우 공개 목적·필드를 별도 지정한다.
- 사용자/역할 화면에서 템플릿 선택 → 담당 조직·교인/기간 → 연락처·상담·반출 추가 권한 → 실제 허용 범위 미리보기 → 저장 순서로 구성한다. 사용자별 예외는 권한표에 드러나야 한다.
- 첫 화면·메뉴·버튼은 역할에 맞게 표시하고 서버/API/다운로드도 같은 정책으로 검사한다. 메뉴 숨김만으로 보호하지 않는다. 담당 변경·연도 전환·퇴임·권한 회수는 다음 요청부터 반영한다.
- 기존 CMS의 ADMIN/SUPER_ADMIN과 목회의 ADMIN/OFFICE/LEADER+CARE만으로 이 요구를 충족할 수 없다. 연결 기능 활성화 전에 공통 권한 정책과 전환 매핑을 먼저 구현·검증한다.

1. **연결 기반**: 접수/계정/조직 매핑과 변경 이력·버전·교회 범위 설계. 기존 관리자와 목회 권한을 역할별 능력으로 명시적 대응. 필요한 최소 DB 역할과 API 경계 준비. 기존 게시물/회원/소속 변경 전 차이 미리보기.
2. **통합 접수함**: 홈페이지 문의와 앱 요청을 유형별 필터·담당자·상태로 처리. 원본 서비스의 검증/보관 규칙 재사용. 목회 일정/기록으로 연결하고 앱의 내 요청 상태 확인. 미연결 계정·비회원·중복 인계·권한 철회 검증.
3. **교인·소속 일원화**: 교인 확인 승인과 기존 교적 연결, 조직별 일괄 배정, 연도 전환, 관심 구독 분리. 변경 결과는 트랜잭션/재시도 가능한 이벤트로 전달하며 성공 확인 전 동기화 완료로 표시하지 않음.
4. **콘텐츠 관리 통합**: 목회 메뉴에 공지·주보·설교·행사 편집을 이전. 서비스는 공유 패키지로 추출하고 apps 간 직접 import 금지. 같은 도메인/세션에서 권한별 메뉴 제공. 별도 관리자 로그인은 전환 검증 뒤 제거.
5. **기존 관리자 정리**: 기능·권한 동등성, 기존 링크 호환, 되돌리기 경로 확인 후 중복 메뉴와 화면 종료. 앱 API와 게시물 주소는 유지.

추천 최종 메뉴: 오늘의 교회 / 접수·돌봄 / 교인·가구 / 조직·모임 / 예배·교육 / 홈페이지·앱 콘텐츠 / 설정·권한. 실제 화면은 담당자에게 필요한 항목만 표시한다.

## 검증 및 운영 전환

- 비공개 요청은 권한 없는 콘텐츠 편집자·조직 리더에게 반환하지 않는다. 교회·조직 범위 검증과 최소 감사 기록 유지.
- 권한 회수, 계정 삭제·탈퇴, 소속 종료, 연도 전환, 연동 중 실패, 재시도, 동시 변경, 원본 만료를 테스트한다.
- 실제 요청이나 회원을 테스트 목적으로 생성·연결하지 않는다. 격리된 자료로 검증하고 운영 전에는 변경 대상과 복구 방법을 준비한다.
- 이 문서는 구현 계획이다. 통합 접수함·소속 동기화·단일 로그인은 아직 완료되지 않았다.
