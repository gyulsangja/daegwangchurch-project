# 통합 관리 운영 전환 — 2026-10-30

## 실제 적용 범위

- 통합 관리 웹은 `apps/ministry`이며 기존 CMS 화면은 대응하는 통합 화면으로 이동한다. 하나의 로그인 화면과 서버 전용 세션을 사용한다. 앱 회원 로그인은 별도 유지한다.
- 공개 콘텐츠 원본과 기존 앱 API는 `apps/admin` 및 공통 서버 패키지에 유지한다. 화면 통합 때문에 기존 모바일 앱의 API 주소를 변경하지 않는다. 기존 CMS 소스를 삭제하는 전환은 아니다.
- 사용자 및 권한에서 목회 역할과 CMS 역할을 함께 저장한다. 두 권한 테이블을 하나의 트랜잭션으로 변경하며 현재 비밀번호, 수정 버전, 본인·마지막 최고관리자 보호 및 감사 이력을 검사한다. CMS 변경에는 CMS 최고관리자 권한도 필요하다.
- 목회 ADMIN, OFFICE, LEADER, CONTENT, COUNCIL을 지원한다. 상담 열람·출력·삭제는 별도 허용과 기존 조직 범위 검사를 따른다. CONTENT는 공개 콘텐츠만, COUNCIL은 이름·연락처·상담·기도 원문이 없는 집계만 본다. 기존 관리자에게 상담 접근을 자동 부여하지 않는다.
- CMS 권한을 해제하면 모임 공지 담당 연결도 해제한다. 목회 이용 중지만으로 별도 CMS 권한까지 해제되는 것은 아니므로 화면에서 두 상태를 함께 확인한다.
- 일정·공지·말씀·주보·사진첩·교회 안내·페이지·사이트 설정·회원·모임 업무를 통합 화면에서 관리한다. 문서 첨부 직접 업로드, 버전 확인 삭제, 활동 기록, 선택한 미사용 파일 정리 도구를 추가했다.
- 문서 업로드는 PDF/HWP/Office/TXT의 허용 형식·크기·기본 구조를 검증한 후 선택 가능해진다. 이는 악성코드 백신 검사가 아니다. 실제 운영 파일 정리는 실행하지 않았다.

## 운영 적용 순서

1. 승인된 006 권한 함수, 007 공개 콘텐츠 삭제 권한 제약, 008 집계 열람 역할을 적용한다.
2. 유효한 기존 CMS 계정 중 목회 권한이 없는 계정만 CONTENT로 연결한다. 기존 목회 권한·정지 상태는 덮어쓰지 않는다. 삭제/익명 인증 계정은 연결하지 않는다.
3. ministry의 `MINISTRY_UNIFIED_ACCESS_ENABLED=true`, `MINISTRY_CONTENT_ROLE_ENABLED=true`로 새 버전을 배포한다.
4. 새 버전 READY 확인 후 admin·website의 `UNIFIED_MANAGEMENT_ENABLED=true`를 설정하고 재배포한다. 오래 열린 CMS 저장 요청은 409로 새 화면 재진입을 안내한다. 앱 API는 유지한다.

## 검증 및 구분

격리 SQL 테스트, 모의 API를 사용하는 모바일 브라우저 검증과 운영 비로그인 접근 제한 점검을 구분한다. 운영 계정의 권한 변경·회원 삭제·파일 정리를 검증 목적으로 실행하지 않는다.

`unified-access-design.md`의 다중 역할 묶음, 담당 교역자의 개별 돌봄 범위, 발행/푸시 권한 분리 및 권한 만료는 후속 설계다. 현재의 다섯 역할과 독립 CMS 권한을 이 설계 전체의 구현으로 해석하지 않는다. 목회 활동에서 공개 초안을 자동 만드는 기능도 모든 활동 유형에 적용된 것은 아니다.
