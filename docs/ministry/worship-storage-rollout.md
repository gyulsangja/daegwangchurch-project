# 예배 기록·주보 파일 이력 운영 적용

2026-10-29. 새 테이블 2개만 추가하며 기존 게시물·파일·계정·사용자 권한을 일괄 변경하지 않는다.

- `005_worship_sessions.sql`: 비공개 ministry 스키마에 날짜별 예배 기록 추가. 회차명·준비/완료/취소/보관 상태·내부 메모·자료 ID·버전·작성자/수정자를 보관. RLS로 현재 교회의 활성 ADMIN만 허용하고 콘텐츠 담당자는 거부. 전용 런타임 계정에 이 테이블의 SELECT/INSERT/UPDATE만 허용하며 DELETE는 부여하지 않는다.
- `20261029090000_bulletin_file_history`: 공개 CMS에 주보-파일 버전 참조 테이블 추가. RLS 활성화, 일반 Supabase API 역할에는 권한을 부여하지 않는다. 기존 CMS 서버 DB 연결로만 관리한다. 기존 자료의 ID/주소를 유지한다.
- 현재 파일과 이후 교체되는 파일을 이력으로 보관한다. 과거 이미 삭제된 PDF는 복구할 수 없다. 주보 PDF는 기존 공개 저장소 파일이므로 과거 공개 URL의 회수/비공개 보장은 하지 않는다. 내부 상담 자료를 주보 이력에 올리지 않는다.
- 적용 순서: 격리 SQL/권한 테스트 → 사용자 운영 적용 승인 → CMS migration deploy → ministry SQL 적용 → 신규 버전 배포 → 로그인/API 보호와 업무 흐름 확인.
- 복구: 문제가 있으면 이전 화면/배포를 복원하고 새 데이터는 유지한다. 새 테이블을 삭제하거나 이전 파일을 정리하는 SQL을 자동 실행하지 않는다. 이전 배포는 파일 교체 시 파일을 삭제하므로 파일 보관 문제가 생기면 교체 작업을 중단하고 수정 배포한다.
- 운영 자료를 가상 테스트용으로 생성하거나 수정하지 않는다. 실제 담당자가 입력하는 정상 업무에만 새 테이블을 사용한다.
