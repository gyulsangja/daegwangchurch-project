# 실제 연결 전 사용성·이용 가치 검토

2026-10-04. 기존 Figma 03 App UI 및 05 Unified Admin, 코드, 로컬 브라우저 체험을 근거로 보완했다. 실제 교인/관리자 인터뷰나 운영 데이터로 효과를 측정한 결과는 아니며, 아래 이익은 구현한 흐름에서 기대하는 효과다.

## 교인이 얻는 이익과 반영한 개선

| 이용 상황 | 기대하는 이익 | 이번 보완 |
| --- | --- | --- |
| 오늘 말씀을 읽고 묵상 기록 | 기록을 다시 찾는 수고 감소, 기도로 자연스럽게 연결 | 홈 작성 후 상태·다시 읽기·기도 이어쓰기 |
| 지난 묵상을 다시 찾기 | 기록한 날짜를 한눈에 확인 | 월 달력·기록 표시·날짜별 목록·전체 목록 전환 |
| 교회 행사와 개인 일정 확인 | 일정 놓침과 중복 표시 혼동 감소 | 월 전체 조회·날짜 표시·공식/저장/개인 필터·중복 제거 |
| 작성 중 로그인이 만료됨 | 긴 글을 처음부터 다시 입력하는 부담 감소 | 같은 계정 재로그인 후 메모리 초안 복원, 버전 충돌 보호 |
| 작은 휴대폰이나 긴 글 읽기 | 날짜와 본문을 더 쉽게 읽고 누름 | 본문 크기·줄간격, 달력 높이, 320px 배치 점검 |
| 처음 사용하는 교인/방문자 | 로그인 필요 범위와 기능 의미를 이해 | MY의 이용 안내, 공개 읽기, 일정 저장≠참가 신청·접수≠예약 확정 설명 |
| 민감한 개인 기록 작성 | 의도하지 않은 전달을 줄임 | 관리자 열람 제외 유지, 상담 전달 동의 복원 금지, 계정 변경 시 초안 제거 |

초안은 영구 저장이나 오프라인 동기화가 아니다. 최대 20개, 마지막 변경 후 30분 동안 현재 실행 메모리에만 있다. 명시적 로그아웃·저장·작성 취소·다른 계정 로그인·새로고침·앱 종료 후 복구되지 않는다. 실제 앱 강제 종료와 네이티브 인증 만료는 실기기에서 확인해야 한다.

## 관리자가 얻는 이익과 반영한 개선

| 이용 상황 | 기대하는 이익 | 이번 보완 |
| --- | --- | --- |
| 교인에게 최신 자료 제공 | 누락된 채널·오래된 시간/장소를 더 쉽게 점검 | 앱 운영 현황의 오늘 할 일·채널별 공개 준비·관리 화면 연결 |
| 홈페이지와 앱에 자료 공개 | 잘못된 채널 공개를 줄임 | 별도 채널 설명, 저장된 앱 발행본 안내, 발행/중단 확인창 |
| 저장 오류 후 다른 화면 이동 | 수정 내용 손실 감소 | 제출 시가 아닌 성공 저장/이동 시 이탈 경고 해제 |
| 회사 설정 없이 사용법 익히기 | 로그인 연결 전에 발행 흐름 숙지 | loopback 전용 가상 발행 체험, 입력 검증·미리보기·취소/확인 |
| 개인 기록과 목회 접수 구분 | 과도한 열람·계정 오인 방지 | 개인 묵상/기도 제외, 앱 가입과 등록 성도 확인 구분, 담당자 정책 대기 명시 |

체험 화면은 실제 CMS 전체나 담당자 업무 화면의 대체물이 아니다. 공개 플래그가 켜졌다는 사실을 연결·발행 성공으로 표시하지 않는다. 신규 상담 담당자 권한을 임의로 확대하지 않았다.

## 구현·검증과 연결 전 남겨야 하는 일

- 기존 단위 47개 + 오프라인/저장소 단위 13개 통과. 윤년·월 경계·한국 시간·여러 페이지·반복 cursor·초안 소유자/만료·알림 소유자/읽음 멱등성/설정 충돌·미리보기 운영 차단을 포함한다.
- 타입·lint·패키지 경계 검사 통과. 브라우저에서 개인 기록 CRUD·저장 실패·충돌·이탈 확인·말씀 저장·일정 중복 제거·로그아웃 회귀 검사를 통과했다.
- Android/iOS/웹 로컬 export와 관리자 production 빌드 통과. 운영 배포나 네이티브 설치/서명 검사는 아니다.
- `scripts/verify-ux.mjs`: 상담 바로가기, 달력, 같은 계정 재로그인 이어쓰기, 홈 작성 후 상태, 기도 이어쓰기, 320px 일정, 이용 안내, 관리자 입력 검증·발행 체험·390px 배치·인증 경계 통과. 화면 전환 완료를 기다린 뒤 다음 행동을 수행한다.
- 스크린샷: `apps/mobile/test-results/ux-*.png` (생성 산출물, Git 제외). 실제 화면을 보고 달력/관리자 작은 화면 배치를 확인했다.
- 알림 DB 서비스는 준비했지만 실제 DB 통합/발송은 검증하지 않았다. 푸시 발송 주체, 기기 토큰, OS 권한, 재시도/중복 방지 작업이 남았다.
- 가입/복구 메일·동의 문구와 버전·탈퇴 보관 기준·상담 담당자 권한은 회사 설정과 정책 확인 후 구현한다. 실제 교인 개인정보를 개발 체험에 입력하지 않는다.
- 운영 migration·seed·배포는 실행하지 않았다. 세부 순서는 [회사 PC 연결 점검표](company-pc-checklist.md) 참조.

## 실제 이용자 검증 시 확인할 질문

후속(2026-10-04): `expo-splash-screen` 설치와 로고 플러그인 연결을 완료했다. 글꼴 로딩 성공/오류 시 해제하며 웹 준비 화면도 로고를 사용한다. 공통 확인/안내창은 제목을 접근성 이름으로 제공하고 짧은 화면에서 스크롤할 수 있다. 일정 필터 줄바꿈, 탭/라디오 그룹 이름을 보완했다. 회원 브라우저 검사에서 320×320 확인창 영역과 취소 클릭까지 확인했다. 네이티브 시스템 글씨 크기·스크린리더·실제 시작 화면은 휴대폰 출시형 빌드에서 별도 확인한다. 구현 기준: [Expo 57 SplashScreen](https://docs.expo.dev/versions/v57.0.0/sdk/splash-screen/).

기본 Expo 설치 아이콘도 기존 `apps/website/public/logo.svg` 교회 원본을 재사용해 교체했다. `scripts/export-mobile-brand.mjs`로 1024px 앱 아이콘·Android 전경/단색·64px favicon·향후 스플래시용 PNG를 재생성한다. [Expo 공식 아이콘 안내](https://docs.expo.dev/develop/user-interface/splash-screen-and-app-icon/)를 따라 iOS용 흰 배경과 Android 중앙 여백을 구분했다. 스플래시 이미지는 준비만 했으며 네이티브 스플래시 플러그인 연결과 실제 설치 후 확인은 남아 있다.

교인에게는 “말씀 찾기→묵상→기도”, “지난 기록 찾기”, “행사를 내 일정에 저장하기”를 도움 없이 수행할 수 있는지 확인한다. 큰 글씨/스크린리더/키보드와 네이티브 뒤로가기도 확인한다. 관리자에게는 “수정 저장→홈페이지/앱 공개 구분→앱 반영 확인”을 수행하도록 하고, 승인·담당자 분담은 실제 교회 운영에 맞게 확정한다. 결과를 확인하기 전 사용률·효율 향상 수치를 주장하지 않는다.
