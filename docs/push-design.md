# 휴대폰 푸시 전환 결정 (2026-10-06)

사용자 요청에 따라 알림센터는 수신 내역으로 남기고, 실제 전달은 앱을 닫아도 동작하는 원격 푸시로 전환한다. 앱 실행/새로고침을 발송 조건으로 삼지 않는다.

| 항목 | 전송 조건 | 시간/횟수 |
|---|---|---|
| 첫시간 주님께 | 본인 선택 + 실제 APP 공개 말씀 존재 | 본인이 정한 한국 시간 이후, 하루 한 번 |
| 새 예배 말씀 | 본인 선택 + APP 공개 | 최초 발행 때 한 번, 수정 시 재발송하지 않음 |
| 중요 공지 | 본인 선택 + 관리자가 중요 공지로 지정 + 공개 기간 유효 | 최초 발행 때 한 번 |
| 교회 행사 소식 | 본인 선택 + 공개된 새 행사 | 최초 발행 때 한 번 |
| 나의 일정 | 본인 선택 + 본인이 만든/저장한 유효한 일정 | 시간 지정은 시작 30분 전(당일 범위), 종일 일정은 오전 8시 |
| 일반 공지·주보·사진 | 홈페이지/앱에서 확인 | 별도 푸시를 늘리지 않음. 꼭 필요한 안내는 중요 공지로 연결 |
| 소속 공지·상담/심방 상태 | 소속 승인/담당자/보관 정책 미정, 기능 비활성 | 이번 활성 대상 제외. 관심 구독자를 승인 교인으로 취급하지 않음 |
| 개인 기도·묵상 기록 | 비공개 자료 | 관리자 발송/잠금 화면 본문 노출 없음 |

모든 항목은 기본 꺼짐. OS 권한과 기기 등록을 명시적으로 완료한 뒤 선택 항목을 받는다. 일반 소식은 한국 시간 22~08시에는 보류하고 기기당 하루 최대 5건, 첫시간과 개인 일정은 사용자가 선택한 시간으로 처리한다. 24시간 이상 지난 소식은 뒤늦게 몰아서 보내지 않는다. 일정 시작 후에는 시간 지정 알림을 보내지 않는다. 첫시간은 당일 말씀만 보낸다.

## 전달 구조

Expo SDK 57 `expo-notifications` → Expo Push Service → Android FCM / iOS APNs. 서버가 5분마다 공개 상태와 수신 동의를 검사해 내역/발송 작업을 만들고, 작업 잠금·결과 영수증으로 중복 실행과 실패를 처리한다. 40명 규모에서 별도 유료 메시징 업체를 추가하지 않는다. Expo 전송료는 무료이나 서버/DB 무료 한도와 앱 배포 비용은 별개다.

Supabase Cron + pg_net에서 배포된 관리자 HTTPS 작업 API를 호출하는 SQL 템플릿을 제공한다. 인증 비밀은 Vault에 두고 앱에는 넣지 않는다. 개발 PC를 켜 두어야 하는 구조를 운영 방식으로 사용하지 않는다. 배포 URL/Expo 프로젝트/FCM·APNs 서명이 없는 현재는 실제 발송을 켜지 않는다.

기기 토큰과 해제용 난수는 기기 SecureStore에 보관하고 서버에는 해제용 난수의 해시만 저장한다. 타인 계정에서 기기를 조회/해제할 수 없으며, 로그아웃은 해제를 요청한다. 오프라인 해제는 재시도 상태를 남긴다. 이미 OS에 전달된 알림 회수는 보장할 수 없어 잠금 화면에는 개인 제목·메모·장소·상담 내용을 넣지 않는다. 누르면 본인 인증 후 알림 원본 접근권한을 다시 확인한다. 토큰은 마지막 갱신 후 30일 만료하고 만료/탈퇴/등록 해제 시 대기 전송을 막는다.

기존 네이티브 앱을 우선한다. 브라우저 미리보기는 기기 푸시를 지원한다고 표시하지 않는다. iPhone 네이티브 배포는 Apple Developer 등록(비영리기관 면제 가능)이 별도로 필요하다. 완전 무료 iPhone 배포가 필수라면 홈 화면 설치형 웹 푸시(PWA)를 별도 배포 방식으로 검토해야 하며, 현재 네이티브 푸시와 동일하다고 안내하지 않는다.
