# 홈페이지·앱 통합 콘텐츠 기준

2026-10-05 연결 후 갱신: 실제 DB에 APP 발행 migration을 적용하고 공개 API를 로컬에서 활성화했다. 별도 PostgreSQL에서 통합 저장·공개·비공개·롤백 검증을 통과했다. 아래 ‘연결 전’ 설명은 당시 기록이며, 기존 말씀은 여전히 관리자 검토·저장이 필요하다. 상세는 [현재 출시 준비](RELEASE_READINESS.md).

2026-10-04 사용자 요청: 한 번 등록하고 두 채널에서 같은 콘텐츠를 제공한다. 이 문서는 과거의 홈페이지/앱 독립 발행 안내보다 우선한다.

| 콘텐츠 | 등록 위치 | 공통 원본과 반영 |
| --- | --- | --- |
| 주일 말씀·첫시간·기타 예배 | 관리자 → 예배 콘텐츠 | 같은 WorshipContent ID. 저장 시 APP revision도 같은 트랜잭션에서 생성. 수정·비공개·삭제 함께 반영 |
| 주보 | 관리자 → 주보 | 같은 Bulletin ID와 PDF. 공개·미삭제·공개 시점·공개 PDF 조건과 날짜/ID 순서를 공유 |
| 공개 공지 | 관리자 → 공지사항 | 기존 공통 원본·공개 정책 사용. 소속 전용 소식은 홈페이지 공개와 구분 |
| 일정 | 관리자 → 교회 일정 | 기존 공통 원본·공개 정책 사용. 앱 달력과 홈페이지 목록은 같은 일정의 다른 보기 |

## 구현

- `service-core.ts`에서 본문 저장과 `sync-publication.ts`를 같은 DB 트랜잭션으로 실행한다. 어느 단계든 실패하면 전체가 롤백된다. 기존 콘텐츠를 잠근 뒤 변경하므로 같은 말씀의 revision 번호 충돌을 막는다.
- 공개 저장은 APP revision을 새로 만든다. 비공개/임시저장/삭제는 APP publication을 제거한다. 개인 묵상에 보존된 당시 말씀은 기존 정책대로 유지한다.
- 앱 별도 발행 버튼을 관리 화면에서 제거했다. 이전 탭의 별도 발행 액션은 상태를 변경하지 않고 새로고침을 안내한다.
- 말씀은 두 채널 모두 고정 → 콘텐츠 날짜 → ID 내림차순이다. 앱 페이지 커서도 이 순서를 따른다. 이전 커서는 호환되지 않으므로 배포 시 목록을 새로 불러온다.
- 예배 유형 명칭은 contracts의 한 정의를 관리자·홈페이지·앱이 공유한다. 영상 제목·설교자·성경 위치·날짜도 같은 저장 원본이다.
- 홈페이지는 주일 말씀/첫시간/주보/공지/일정을 별도 영역으로 자동 조회한다. 홈 편집 화면에서 사용하지 않는 옛 제목·표어 필드는 숨기고 기존 값만 보존한다. 영역 숨기기와 원본 콘텐츠 비공개는 서로 다른 설정임을 안내한다.

## 연결 전후 필요한 확인

- 앱 API 활성화 환경변수는 자동 변경하지 않았다. 운영 연결 후 켜야 앱에서 공개 콘텐츠를 읽는다.
- 이미 저장된 말씀을 자동 일괄 발행하지 않았다. 관리자 편집 화면은 원본과 APP 버전의 차이를 표시한다. 해당 콘텐츠를 한 번 저장하면 통합된다. 앱에 따로 업로드할 필요는 없다.
- 기존 말씀 revision/publication 마이그레이션이 실제 DB에 적용되어 있어야 한다. 이번 작업에서 운영 DB나 마이그레이션을 실행하지 않았다.
- 직접 SQL로 본문만 바꾸면 앱 snapshot까지 갱신되지 않는다. 운영 콘텐츠 수정은 통합 관리자 저장 서비스를 사용한다.
- 앱에는 공개 PDF 없는 주보를 제공하지 않던 정책을 홈페이지에도 적용했다. 따라서 손상·비공개·삭제된 PDF의 주보는 두 채널에서 함께 숨겨진다.
- 기존 모임 소식·회원 기능의 메모리 체험 API는 운영 저장소가 아니다. 실제 연결 전까지는 홈페이지와 체험 앱의 샘플 데이터가 동일해지는 것이 아니다.

## 검증

단위 테스트로 한 번 저장·수정의 동일 내용, 비공개·삭제, 앱 저장 실패 시 전체 롤백, 공통 순서 및 커서 경계를 확인했다. 실제 PostgreSQL 통합 테스트도 새 정책에 맞게 갱신했다. 현재 PC에 Docker가 없어 해당 통합 테스트는 실행하지 못했으며 실제 DB 연결 후 임시 테스트 DB에서 실행해야 한다. 운영 DB를 테스트 대상으로 사용하지 않는다.
